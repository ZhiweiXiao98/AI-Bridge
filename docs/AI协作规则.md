# AI 协作与工程规范

## 工作方式

1. 修改前检查工作区、当前状态和相关实现，核对类、方法、信号与调用方。
2. 阅读关键模块的完整调用链；输出被截断时继续定位必要内容。
3. 在用户授权范围内完成实现、验证与文档同步。需要用户选择时，提供已核对的具体方案和影响。
4. 保留已有改动；提交范围应与本次任务一致。
5. 使用中文说明具体行为、证据和限制。普通文档直接描述当前实现；历史记录注明日期与阶段。

## 架构边界

| 层级 | 职责 |
| --- | --- |
| 面板与页面 | UI、请求信号和结果展示 |
| MainWindow | 注册面板、连接信号和协调窗口 |
| Worker / RemoteWorker | 本地执行、远程请求及结果传递 |
| 服务与运行时 | 业务规则、状态转换、工具执行和持久化 |

面板遵循 `DockablePanel`、`PanelManager`、`WorkspaceManager` 的现有接口。标题栏交给基类管理，局部控件使用局部样式；主题颜色来自主题系统。

本地和远程接口应保持一致的结果、错误与超时语义。需要返回值的 RPC 提供响应通道。项目切换同步客户端和服务端，软件路径使用 `APP_ROOT`，项目路径使用 `ProjectContext`。

## 验证要求

- 写入后检查实际改动和行为；执行与改动相关的测试。
- 修改启动、页面导入、面板、Worker 或远程通信时，验证导入链、基类接口、信号连接和必要的启动/交互流程。
- 修改会话、快照、布局或配置持久化时，验证重新加载后的结果。
- 检查异常、取消、空状态与远程返回，确保调用方有对应处理。
- 报告实际执行命令、通过/失败结果和未覆盖环境。手工验收项在获得证据后勾选。

测试方法见 [tests/README.md](../tests/README.md)，文件写入与沙盒协议见 [AI_README.md](../AI_README.md)。

## 文档维护

当前事实写入[项目状态](当前项目状态.md)，模块职责写入[结构导航](项目结构导航.md)，使用方法维护在对应主题文档。历史修复与验证证据追加到 [AI_JOURNAL.md](../AI_JOURNAL.md)。

更新现役文档时，删除失效路径、已完成的建设待办和被替换的版本描述；保留仍有效的使用约束、实现边界与验收要求。

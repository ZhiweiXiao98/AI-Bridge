# 上下文压缩机制与验收

> 复核日期：2026-09-26。当前压缩由 `ContextCompactionOrchestrator` 执行，消息模型为 `ConversationMessage`。

## 触发与处理

`APISource` 在请求前检查自动压缩，也提供手动压缩入口。自动阈值根据上下文总预算、输出预留与 `compact_buffer` 计算；阈值无效、历史不足或压缩状态禁止尝试时返回相应原因。

当前历史划分保留最近 6 条消息，从更早消息中选出 `compactible` 项作为摘要候选。摘要由规则提取可见消息的内容片段，带角色与消息类型，最多 12 项、每项最多 120 个字符。随后以 `compact_summary` 消息和保留区重建历史。

压缩状态记录成功、失败、摘要预览和处理数量；达到失败阈值后可进入等待手动重试的状态。会话存储负责压缩状态与上下文持久化。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `app/core/context_compaction.py` | 阈值判断、历史划分、规则摘要与压缩执行 |
| `app/core/context_compaction_state.py` | 压缩状态及失败控制 |
| `app/core/context_message_models.py` | 结构化消息、可见性与压缩标记 |
| `app/core/context_manager.py` | 分层预算、历史替换和 Provider 消息构造 |
| `app/core/api_source.py` | 请求前检查、手动触发与快照 |
| `app/core/conversation_store.py` | 会话与压缩状态保存、重载 |

## 使用与排查

1. 在上下文工作台检查各层预算、消息及最近请求快照。
2. 确认目标会话后触发手动压缩，检查返回原因和摘要内容。
3. 核对下一次请求实际携带的历史、工具反馈及预算。
4. 重新加载会话，检查摘要、保留消息和压缩状态。

# 上下文系统与请求快照

> 复核日期：2026-09-26。本文描述上下文组织、持久化与使用入口。

## 能力与入口

API 上下文由系统提示、长期记忆、工作记忆、短期历史及输出预留组成。聊天栏显示容量环和各部分明细；上下文工作台提供内容查看、编辑、清理、历史操作、手动压缩与最近请求快照。

普通 API 流式消息可携带 thinking 内容，最终以消息 segment 保存。请求快照随会话 JSON 落盘，重新加载后可以读取最近一次快照；没有快照时显示说明。

Browser 模式读取网页消息。`browser_stateless` Profile 按本地上下文重新组织每轮网页请求；普通 Browser 与 HTTP API 的上游处理各有入口，后续工具执行使用共享运行时。

## 组成

| 代码 | 职责 |
| --- | --- |
| `app/core/context_manager.py` | ContextConfig、TokenCounter、分层记忆与请求消息构造 |
| `app/core/context_message_models.py` | `ConversationMessage` 及历史/请求字典转换 |
| `app/core/context_compaction.py` | `ContextCompactionOrchestrator`：判断压缩、划分历史和构造摘要 |
| `app/core/context_compaction_state.py` | 压缩状态归一化 |
| `app/core/conversation_store.py` | 会话内容、模型覆盖、压缩状态与 `last_request_snapshot` 持久化 |
| `app/core/api_source.py` | 有效 Profile、请求组装、快照捕获与读取 |
| `app/core/prompt_runtime/` | Prompt 来源、系统策略与 Skills 说明 |
| `app/core/worker_modules/worker_context_workspace.py` | 上下文工作台操作和 UI payload |
| `app/ui/components/panels/context_workspace_panel_logic.py` | 工作台交互、快照弹窗与空状态 |

## 持久化与路径

API Source 使用 `{APP_ROOT}/config/conversations/` 保存对话。记录包含项目元数据，具体目录策略见[项目切换](项目切换功能改造计划书.md)。

快照中的工具候选等对象在保存时转换为 JSON 可表示的结构。变更快照内容后需同步保存，验证时应重新构造会话存储并读取结果。

## 调试顺序

1. 确认目标会话、Profile、模型和 reasoning 覆盖。
2. 查看上下文容量及分层内容，确认实际预算来源。
3. 打开最近请求快照，核对系统提示、历史、工具协议与 Provider 请求。
4. 修改或压缩后重新读取；涉及持久化时重载会话。
5. 根据 `conversation_id`、流式事件和工具反馈定位 UI 与服务端的对应关系。

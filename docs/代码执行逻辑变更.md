# 代码执行逻辑反转 - 变更总结

## 📅 日期
2024-01-XX

## 🎯 变更目标
将代码执行逻辑从"默认执行"改为"默认不执行"，提高安全性和明确性。

## 🔄 核心变更

### 修改前（旧逻辑）
- 默认：执行所有代码块
- 例外：带 # NO_EXEC 标记的不执行
- 问题：AI 容易忘记给示例代码加标记，导致误执行

### 修改后（新逻辑）
- 默认：不执行任何代码块（安全）
- 例外：带 # EXEC、# RUN 或 # EXECUTE 标记的才执行
- 优势：示例代码无需标记，执行需要显式声明

## 📝 使用方式

### 执行代码（需要标记）
在代码块首行添加 # EXEC、# RUN 或 # EXECUTE 标记

### 示例代码（无需标记）
不需要任何标记，默认不会被执行

### 保存代码（带 filename，不执行）
即使有 # EXEC 标记，如果代码包含 filename 标记，也不会被执行（只保存）

## 🎯 优势

1. **更安全**：默认不执行，避免误执行示例代码
2. **更明确**：执行是特殊操作，需要显式声明
3. **更符合直觉**：示例代码无需任何标记
4. **更符合最小权限原则**：只执行明确标记的代码

## 📊 影响范围

- ✅ 向后兼容：旧的 # NO_EXEC 标记会被忽略（因为默认就不执行）
- ⚠️ 需要适应：AI 需要学习在诊断代码前加 # EXEC
- ✅ 用户友好：示例代码无需标记，更简洁

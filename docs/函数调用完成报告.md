## 🎯 目标
解决 AI 无法正确调用 Skills 的问题，实现标准的 Function Calling 架构。

## ✅ 完成的工作

### 1. 核心架构改造
- BaseSkill 添加 get_tool_definition() 方法
- 所有 Skills 实现 JSON Schema 参数定义
- SkillsManager 支持获取所有工具定义和生成系统提示词
- ToolRouter 支持解析和执行工具调用

### 2. 工具调用格式
使用代码块包裹格式，避免 HTML 解析问题：

使用三个反引号加 tool_call 标记
{
  "name": "skill_name",
  "arguments": {
    "param": "value"
  }
}

### 3. Worker 集成
在 Worker 中添加工具调用检测逻辑：
- 优先检查 tool_call 代码块
- 如果找到，调用 ToolRouter 执行
- 否则继续检查 python 代码块（原有逻辑）

执行顺序：
1. 检查 ```tool_call
2. 调用 ToolRouter 执行工具
3. 返回结果给用户
4. 如果不是 tool_call，检查 ```python
5. 继续原有的执行标记检查

### 4. 支持的 Skills
- code_execution: 在 Docker 沙盒中执行 Python 代码
- file_operations: 读取文件、列出目录
- knowledge_search: 在代码库中进行语义搜索

### 5. 关键修复
- 统一参数名（action 替代 operation）
- 使用代码块格式避免浏览器 HTML 解析
- 在 Worker 中优先检查工具调用
- 修复正则表达式匹配代码块格式

## 🔧 技术细节

### 完整工作流程
1. AI 生成包含 tool_call 代码块的回复
2. Worker 检测到 ```tool_call
3. 提取完整文本传递给 ToolRouter
4. ToolRouter 使用正则提取 JSON
5. 解析并验证参数
6. 调用对应 Skill 的 execute 方法
7. 返回执行结果
8. Worker 发送结果给用户

### 关键代码位置
- app/core/skills/base.py: 工具定义基类
- app/core/skills/manager.py: 工具管理和提示词生成
- app/core/services/tool_router_service.py: 工具路由和执行
- app/core/worker.py: 工具调用检测（第 169-197 行）

## 🚀 使用示例

AI 现在可以这样调用工具（使用三个反引号加 tool_call）：
{
  "name": "file_operations",
  "arguments": {
    "action": "read_file",
    "path": "app/main.py",
    "max_lines": 50
  }
}

# Subagent 后台任务

> 复核日期：2026-09-26。后台任务由 `WorkerSubagentBridge`、`SubagentThread` 和事件总线协调。

## 配置与使用

设置页的 Subagent 分区管理启用状态、模型层级和任务配置。`SubagentConfig` 解析 `lite` / `core` 的 Profile 或 Chain 引用；`SubagentLLMRouter` 使用 API Provider 执行后台请求。

启动需要启用配置且具备 API Key。回复完成时，Worker 将回复、会话标识、模式和近期上下文交给事件总线；建议任务生成结果后通过信号送到客户端。

资料整理任务支持显式转换请求。配置为 polling 时，SubagentThread 创建定时器触发整理任务。资料整理面板与 CLI 的独立使用方法见[资料整理说明](资料整理Agent实施计划书.md)。

## 模块位置

| 模块 | 职责 |
| --- | --- |
| `app/core/worker_modules/worker_subagent_bridge.py` | 生命周期、回复事件、文档转换请求和结果信号 |
| `app/core/worker_modules/worker_subagent_notify.py` | 回复完成时的上下文整理与通知 |
| `app/core/subagent/subagent_config.py` | 模型层级、任务开关及触发配置 |
| `app/core/subagent/subagent_thread.py` | 任务注册、事件处理与整理定时器 |
| `app/core/subagent/subagent_event_bus.py` | 事件订阅与派发 |
| `app/core/subagent/subagent_llm.py` | API 模型路由 |
| `app/core/subagent/tasks/` | 建议、压缩和资料整理任务 |

`WorkerDaemonBridge` 继承 `WorkerSubagentBridge`；Worker 保留 daemon 属性及信号别名供现有调用方使用。对接接口时应核对具体定义与接收端。

## 验收重点

- [ ] 启用、禁用和热重载后的线程与模型状态一致。
- [ ] 回复完成通知携带正确会话与上下文。
- [ ] 模型不可用、超时和任务异常获得明确反馈。
- [ ] polling 整理、显式转换与手动面板生成的结果一致。
- [ ] 建议展示、选用和过期处理符合当前聊天交互。

建议质量与反馈机制的后续设计见[建议助手演进方案](建议助手三阶段演进方案.md)。

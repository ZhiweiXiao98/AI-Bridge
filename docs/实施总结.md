## 需求 2：待发消息附加到工具执行结果

### 修改文件
1. `app/ui/pages/chat/page.py`
   - 第 113 行：设置 `input_area.worker = self.worker`
   - 第 114 行：设置 `worker.input_area = self.input_area`（双向引用）

2. `app/core/worker.py`
   - 第 23 行：添加 `self.pending_user_message = None` 属性
   - 第 915-918 行：添加 `set_pending_message()` 方法
   - 第 920-924 行：添加 `get_and_clear_pending_message()` 方法
   - 第 166-175 行：在工具执行位置 1 检查并附加待发消息
   - 第 443-455 行：在工具执行位置 2 检查并附加待发消息

3. `app/ui/pages/chat/input_area.py`
   - 第 185-187 行：在 `on_send` 中，消息进入待发状态时通知 worker

### 工作流程
1. AI 正在生成回复（busy 状态）
2. 用户在输入框输入新消息并点击发送
3. 消息进入"待发状态"（queued_payload）
4. input_area 通知 worker 保存待发消息
5. 工具执行完毕（代码块执行完成）
6. worker 检查是否有待发消息
7. 如果有，将待发消息附加到工具执行结果中
8. **清空 input_area.queued_payload，避免 check_auto_send 重复发送**
9. 一起发送给 AI

### 附加格式
工具执行结果
============================================================
📩 用户待发消息:
用户输入的内容

### 插话问题修复
**问题**：工具执行完毕后，AI 状态变为 idle，触发 `check_auto_send`，导致待发消息被单独发送。

**解决方案**：
1. 建立 worker ↔ input_area 双向引用
2. worker 附加待发消息后，清空 `input_area.queued_payload`
3. 避免 `check_auto_send` 重复发送

### 测试
运行：`python tests/test_pending_message.py`

## 🔄 2024-01-XX - 代码执行逻辑反转

### 变更内容
**从"默认执行"改为"默认不执行"**

### 修改前（旧逻辑）
- 默认：执行所有代码
- 例外：加了 # NO_EXEC 的不执行

### 修改后（新逻辑）
- 默认：不执行任何代码
- 例外：加了 # EXEC 的才执行

### 优势
1. ✅ 更安全：AI 生成的代码默认不执行
2. ✅ 更明确：执行是特殊操作，需要显式声明
3. ✅ 更符合直觉：示例代码无需标记
4. ✅ 更符合最小权限原则

### 使用方式
在代码块首行添加 # EXEC 标记

### 支持的标记
- # EXEC
- # RUN
- # EXECUTE

### 修改的文件
1. app/core/services/tool_router_service.py - 反转检测逻辑
2. tests/test_example_code_filter.py - 更新测试用例
3. README.md - 更新系统提示词
4. 实施总结.md - 更新文档

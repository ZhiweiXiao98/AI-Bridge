# 建议助手三阶段演进方案

## 2026-05-03 | 建议助手从“能用”到“好用且懂用户”的演进计划 | 🚧 进行中

### 1. 背景
当前建议助手已经打通基础链路：**接收输入 -> LLM 生成 -> 输出建议**。现阶段已完成的核心修复包括：
- 回复完成时补充 `recent_context`
- `worker_subagent_bridge` 兼容并转发上下文
- `SuggestTask` 将最新回复、最近上下文、模式一起喂给模型
- `Prompt/Subagent_Suggest.md` 已收口为“必须结合上下文”的规则

本方案关注建议的上下文相关性、表达风格和稳定性。

### 2. 目标
把建议助手从基础可用升级为：
- 更像用户的表达方式
- 更懂当前对话意图
- 更少泛化建议
- 更稳定地处理长上下文
- 更容易通过数据验证效果

### 3. 当前判断
建议助手的优化优先级应当按以下顺序推进：
1. **记忆与人设系统**
2. **上下文折叠与 token 控制**
3. **建议结果反馈闭环**
4. **MCP 检索能力**
5. **多 Agent / 投机执行**

其中前 3 项适合当前阶段落地，后 2 项更适合作为后续升级能力。

---

## 第一阶段：记忆与人设系统

### 目标
让建议助手根据对话记忆和风格偏好生成符合用户表达习惯的建议。

### 关键能力
- **会话记忆**：保留当前会话最近对话和意图
- **长期风格记忆**：记录常用口头禅、常见句式、禁用表达、偏好语气
- **反馈记忆**：记录哪些建议被采纳、修改、忽略

### 设计建议
建议拆成三层：
- 短期上下文：当前对话内容、最近几轮、当前意图
- 长期风格记忆：常用表达、禁用词、语气偏好
- 行为反馈记忆：点击、拖拽、采纳、忽略

### 实施方式
- 将风格偏好整理成可加载的 Markdown / JSON 配置
- 从“最终被用户保留的回复”中提取风格特征
- 定时或手动生成 `Style Guide`
- 在下一次 prompt 中附加风格约束

### 验证标准
- 建议语气是否逐步接近用户习惯
- 是否减少了空泛句式
- 是否更少出现“继续 / 好的 / 嗯嗯”这类低信息建议

---

## 第二阶段：上下文折叠与 token 控制

### 目标
让建议助手在长对话、长群聊、长邮件链场景下依然稳定运行，不出现上下文污染或 token 爆炸。

### 关键能力
- **微压缩**：去掉寒暄、重复系统消息、无效噪声
- **滑动窗口**：保留最近 N 轮完整原文
- **摘要折叠**：把更早历史折叠成结构化摘要
- **Prompt Cache**：把长期不变的风格部分做缓存化管理

### 推荐折叠结构
建议不要只生成一段纯文本摘要，而是拆成：
- 事实摘要
- 意图摘要
- 风格摘要
- 最近窗口原文

### 实施方式
- 为建议任务增加上下文预处理层
- 设定 token 预算上限
- 超限时自动触发摘要折叠
- 保留最近原文，避免上下文变“只剩结论没有细节”

### 验证标准
- 长对话下建议是否还能保持稳定
- token 消耗是否可控
- 是否出现明显的历史噪声干扰

---

## 第三阶段：反馈闭环

### 目标
根据用户反馈改进建议的有效性。

### 关键能力
- 记录建议是否被点击
- 记录建议是否被拖拽到输入框
- 记录建议是否被直接发送或二次修改
- 统计不同模式下的采纳率

### 实施方式
- 给建议卡片增加轻量埋点
- 对每次建议保存最小必要元数据
- 后台定期分析高采纳类型
- 用反馈结果优化排序和 prompt

### 验证标准
- 哪类建议最容易被采纳
- 哪类建议看起来合理但没人用
- 不同 prompt 版本的实际效果差异

---

## 第四阶段：MCP 检索能力

### 目标
让建议助手不仅“像你说话”，还能在必要时“查清事实后再说”。

### 适用场景
- 涉及代码状态
- 涉及项目进展
- 涉及文档内容
- 涉及外部系统状态

### 说明
这一阶段通过检索提高建议的事实依据。

### 建议方式
- 以工具插件方式接入检索能力
- 当检测到需要查证的场景时，后台拉取事实
- 再结合用户风格生成建议

### 风险
- 系统复杂度上升
- 工具链路变长
- 需要严格控制失败降级

---

## 第五阶段：多 Agent / 投机执行

### 目标
把复杂任务拆给多个角色处理，提高候选质量和响应速度。

### 可选模式
- 研究员：负责查资料和事实
- 打字员：负责按用户风格生成文本
- 审核员：负责检查风险和一致性

### 适用范围
适合高价值、强审查、复杂事实查证场景；不建议作为当前阶段的默认路径。

### 风险
- 架构成本高
- 调试困难
- 容易过度设计

---

## 推荐实施顺序

### 近期
- [ ] 做长期风格记忆
- [ ] 做上下文折叠
- [ ] 做建议反馈闭环

### 中期
- [ ] 做模式区分优化（browser / API 分风格）
- [ ] 做建议去重与意图分层
- [ ] 做低置信度静默策略

### 长期
- [ ] 接入 MCP 检索
- [ ] 引入多 Agent 协作
- [ ] 做投机执行与预判草稿

---

## 验收标准
建议助手达到以下状态时，认为第一阶段目标达成：
- 建议内容贴合当前对话与用户意图
- 建议语气更贴近用户风格
- 建议在长上下文中仍能保持稳定
- 可以通过点击率 / 拖拽率 / 采纳率判断优化是否有效

---

## 结论
当前最值得先做的是：
1. 记忆与人设
2. 上下文折叠
3. 反馈闭环

MCP 和多 Agent 可以作为后续能力预留，不建议与当前主线一起全面展开。

> 最后编辑时间：2026-04-18
> 状态：初版
> 适用范围：阶段 A / B / C / D / E 完成后的第一轮回归验证
> 用途：用于验证 API 模式回合状态机、UI 收口、工具闭环、兼容链和快照字段是否按预期工作。

# 一、测试目标

本清单用于验证以下改造是否真正落地：

```md
[ ] round_state 是否贯通后端 -> worker -> UI
[ ] UI 是否不再把 end_stream 当作整轮完成
[ ] tool loop 是否仍能正常执行
[ ] markdown tool_call / legacy exec code 是否未回归
[ ] tool_feedback 是否带有 ephemeral 标记
[ ] snapshot 是否能看到 round_state / selected_tool_protocol / ephemeral_tool_rounds
[ ] 切会话 / 切模式是否不会留下残影
[ ] native FC 骨架是否已预留但未误接入真实执行链
```

# 四、回归测试项

## T1. API 普通文本消息发送

### 目的

验证 API 模式基础发送仍可工作，没有被状态链改造破坏。

### 步骤

```md
1. 打开聊天页，切到 API 模式
2. 进入一个现有会话或新建会话
3. 发送普通文本，例如：你好，请用一句话回复
4. 观察 UI、Header、最终历史消息
```

### 预期

```md
[ ] 用户消息能正常显示
[ ] assistant 能正常返回文本
[ ] 不出现报错或明显卡死
[ ] 最终消息能进入正式历史
```

### 重点观察

```md
[ ] `api_send(..., stream=True)` 是否正常启动
[ ] worker 是否未报 API 循环异常
```

---

## T2. 首轮流式输出显示

### 目的

验证流式首轮仍能正常显示，且未被 UI round_state 改造破坏。

### 步骤

```md
1. 在 API 模式下发送一个会触发较长回答的问题
2. 观察流式临时气泡是否出现
3. 观察流式文本是否持续追加
4. 流式结束后观察临时气泡是否被正确清理
```

### 预期

```md
[ ] 临时流式气泡出现
[ ] 文本块持续追加
[ ] 流式结束后临时气泡销毁
[ ] 不会立即错误闪回全量历史（若后续还要进入工具阶段）
```

---

## T3. round_state 基础流转

### 目的

验证状态链已打通。

### 步骤

```md
1. 发送一条普通消息
2. 打开快照 / 调试浮窗
3. 检查本轮 snapshot 字段
4. 如可能，观察 UI Header 状态变化
```

### 预期

```md
[ ] snapshot 中存在 `round_state`
[ ] snapshot 中存在 `selected_tool_protocol`
[ ] snapshot 中存在 `tool_candidates`
[ ] snapshot 中存在 `ephemeral_tool_rounds`
[ ] snapshot 中存在 `finalized`
```

### 重点观察

至少应能看到：

```md
streaming_initial_reply
...
finalized
```

若命中工具，还应看到：

```md
detecting_tools -> running_tools -> generating_followup -> finalized
```

---

## T4. UI 不再只依赖 `_active_stream_id`

### 目的

验证 UI 正式改为以 round_state 控制渲染。

### 步骤

```md
1. 发送一条会触发工具调用的消息
2. 观察流式结束后 UI 表现
3. 在工具执行期间观察消息区是否立刻重绘正式历史
4. 观察 finalized 后是否由正式历史接管
```

### 预期

```md
[ ] 流式结束后，如果仍处于 detecting_tools / running_tools / generating_followup，不会立刻重绘全量历史
[ ] 工具执行期间 UI 保持稳定
[ ] finalized 后正式历史接管 UI
```

---

## T5. Header 状态提示

### 目的

验证用户在工具阶段有明确感知，不再误以为系统卡死。

### 步骤

```md
1. 发送一条会触发工具调用的消息
2. 观察 Header 状态文本
```

### 预期

至少能看到类似文本：

```md

[ ] 正在执行 xxx...
[ ] 正在生成后续回答...
```

## T6. markdown `tool_call` 兼容链

### 目的

验证 markdown 围栏 `tool_call` fallback 在阶段 C 后未回归。

### 步骤

让模型输出类似：

```markdown
tool_call
```json
{
  "name": "file_operations",
  "arguments": {
    "operation": "read_file",
    "path": "README.md"
  }
}
```
```

然后观察工具执行结果与后续回复。

### 预期

```md
[ ] 工具能被识别并执行
[ ] tool_feedback 能进入历史
[ ] followup 能继续生成
[ ] snapshot 中 `selected_tool_protocol` 能反映 markdown_tool_call 或对应协议来源
```

## T7. legacy exec code 兼容链

### 目的

验证 legacy `# EXEC` 代码块路径在结构统一后未回归。

### 步骤

让模型输出形如：

```python

print("hello from exec")
```

并确保该代码块不会被 filename 保存链误识别。

### 预期

```md
[ ] legacy exec code 能被识别
[ ] 代码能执行并返回输出
[ ] `code_execution_completed` 信号相关行为不报错
[ ] snapshot / round_result 结构未报兼容错误
```

# 七、结论标准

如果第一轮回归后满足以下条件，可视为本轮改造基本成立：

```md
[√] 普通文本发送代码路径正常（待真实发送验证）
[√] 流式首轮显示代码路径正常（待真实 UI 验证）
[√] round_state 后端到 UI 代码链路已贯通（待真实信号观察）
[√] 工具阶段 UI 不误重绘的控制逻辑已具备（待真实工具阶段验证）
[√] markdown tool_call / legacy exec code 代码路径均未回归（待真实执行验证）
[√] tool_feedback 的 ephemeral 标记代码层可见（待快照/UI 查看）
[√] 切会话 / 切模式清理逻辑已具备（待真实快速切换验证）
[√] snapshot 字段足够支撑调试（待真实快照查看）
```

若以上任一核心项失败，则应优先修复，不建议继续叠加新功能。

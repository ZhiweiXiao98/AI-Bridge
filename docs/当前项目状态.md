# Data-Bridge 当前项目状态

> 复核日期：2026-09-26。能力说明已与源码核对；自动化验证记录见 [AI_JOURNAL.md](../AI_JOURNAL.md)。真实 Provider、Browser、Mobile 和 Rhino 的完整端测需单独记录。

## 产品与架构

Data-Bridge / AI Bridge 是一套由 FastAPI 服务端、PySide6 桌面客户端和 Web/PWA 移动端组成的 AI 智能体工作台。Browser 模式通过 Chrome CDP 读取和发送网页消息；API 模式通过 Provider 接口处理对话。两种模式共用工具运行时、项目上下文和客户端界面。

## 当前能力

| 能力 | 实现与入口 |
| --- | --- |
| Browser 消息处理 | CDP 驱动、DOM 增量提取、规范化消息存储、回合状态机和工具结果回传；代码位于 `app/core/driver/`、`app/core/browser_sync/`、`app/core/round_state/` |
| API 对话 | 多 Profile、Gemini / OpenAI-compatible / MiMo 接入、普通流式输出、会话级模型与 reasoning 配置；入口为 `app/core/api_source.py`、`app/core/llm_provider.py` |
| 原生工具 | OpenAI-compatible 支持非流式和流式 tool calls、工具执行、结构化反馈及后续请求；详见[工具协议](API模式原生工具调用与提示词分流计划.md) |
| 模型与工具探测 | 设置页通过带请求 ID 的 RPC 获取探测结果，模型列表回写 Profile；MiMo 模型列表过滤音频模型，在线列表不可用时可使用代码内置目录 |
| 思考与 Skills 引用 | 普通 API 流式回答传递 thinking 增量并保存为消息 segment；输入 `/` 展开 Skills 建议，选择后生成 `$skill_name` 引用 |
| 上下文 | Prompt 来源、分层预算、自动/手动压缩、请求快照落盘、最近快照恢复和空状态说明；详见[上下文系统](上下文系统建设计划.md) |
| 项目与会话 | 顶部菜单及聊天栏提供项目切换；知识库按项目标识隔离，API 对话保存项目元数据并分组展示；详见[项目切换](项目切换功能改造计划书.md) |
| KnowledgeSearch | Chroma 索引、fastembed 嵌入、重排、串行执行队列、缓存、健康状态和降级；详见[知识库说明](知识库V2重构计划.md) |
| 设置与插件 | 侧边导航组织设置分区；面板使用 PanelManager 和插件生命周期；详见[设置页说明](设置界面模块化重构计划书.md)、[插件设计](插件系统设计.md) |
| 文档生成 | CLI 转换、面板生成与预览、生成状态跟踪；详见[资料整理说明](资料整理Agent实施计划书.md) |

## 开发与验收重点

| 优先级 | 工作 | 验收边界 |
| --- | --- | --- |
| P0 | API 原生工具与 thinking | 补齐 Gemini native tools、native tools 多轮 reasoning 回放，并用真实 Provider 验证工具调用至最终答复 |
| P0 | 统一模型能力描述 | reasoning 控件已有能力解析；tools、stream、模型目录来源和 fallback 策略需要形成一致的配置与展示口径 |
| P0 | 上下文控制 | 对齐设置页和上下文工作台的预算配置、请求快照及实际 Provider payload |
| P1 | Browser 工具结果绑定 | 验证结果及时进入 ToolCallCard、AutoFix 展开后的 `block_key` 稳定性和流式轻量渲染 |
| P1 | 项目切换 | 收敛 `os.chdir()` / `os.getcwd()` 依赖，补多项目会话聚合与跨项目操作路由，记录完整切换验收 |

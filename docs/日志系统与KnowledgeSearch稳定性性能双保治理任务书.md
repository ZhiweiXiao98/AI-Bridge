# KnowledgeSearch 稳定性排查与验收

> 复核日期：2026-09-26。本文用于定位检索、模型运行时与服务连接问题，并记录实际环境中的稳定性证据。

## 当前入口

KnowledgeSearch 使用 `KnowledgeServiceV2`、串行执行队列、Chroma 索引、fastembed 嵌入及重排流程，并提供缓存、健康状态与降级。模块职责和恢复入口见[知识库说明](知识库V2重构计划.md)，日志使用见[日志与调试](统一日志与调试体系改造计划书.md)。

## 排查步骤

1. 记录 Python、模型运行时、检索后端与运行方式，确认目标项目和索引。
2. 收集服务端退出码、错误栈、检索调用日志及客户端连接状态。
3. 区分模型初始化、索引操作、嵌入、重排、队列等待与结果回传阶段。
4. 查看健康状态、缓存及降级原因，确认实际采用的检索路径。
5. 对照相同输入复现，记录耗时、返回结果和进程存活情况。

客户端连接失败说明服务连接不可用；确定根因需要服务端证据。日志、模型库、索引库和线程行为分别核对。

## 验收范围

- [ ] 冷启动首次检索与连续检索均返回明确结果。
- [ ] 多次请求通过队列正确执行，超时和取消能收口。
- [ ] 嵌入、重排或索引异常时，健康状态与实际降级一致。
- [ ] 主路径恢复后重新获得预期检索结果。
- [ ] 项目切换后使用正确索引，跨项目结果保持隔离。
- [ ] 长时间运行期间，进程、连接、内存和延迟保持可观测。
- [ ] 在当前 fastembed / ONNX、TextCrossEncoder 与 Chroma 组合上记录端到端证据。

性能方法见[知识库基准测试](知识库V2基准测试计划.md)。是否增加进程隔离应依据实际崩溃与资源证据评估。

# Browser 同步与渲染验收

> 复核日期：2026-09-26。本文聚焦消息身份、顺序、流式收口和工具结果绑定。现有链路见[增量同步说明](浏览器模式消息同步增量化计划.md)。

## 维护边界

1. 网页 DOM 由 Driver 提取和解析，Worker 协调规范化与同步。
2. 消息携带会话、角色、顺序、修订及 segments；序列字段用于同步与投影。
3. 客户端依照服务端消息更新列表和气泡，并处理流式临时展示。
4. 工具调用与结果通过 `tool_call_id`、`block_key` 等标识关联。
5. 内容变化检测需同时覆盖稳定消息、流式尾部与折叠/展开后的代码。

## 已有实现入口

| 范围 | 代码 |

## 运行验收表

| 场景 | 观察结果 |
| --- | --- |
| 同 ID、不同角色 | 用户和 AI 消息都保留，顺序正确 |
| 长回复与代码流式输出 | 内容持续更新，结束时与最终 DOM 一致 |
| 定向提取失败 | 成功抓取后才推进对应稳定签名，后续可重试 |
| AutoFix 展开 | 完整代码可见，工具卡与结果仍对应 |
| 工具结果先于气泡到达 | 后续气泡创建后能绑定结果 |
| DOM 工具回流 | 结果归入目标调用，重复事件不产生重复内容 |
| 会话切换和重新连接 | UI 与目标会话一致，快照及增量顺序可追溯 |
| 虚拟滚动和历史加载 | 可见窗口变化时消息顺序、角色和工具绑定正确 |

## 记录证据

每次验收记录网页环境、会话与操作步骤、相关日志和实际显示结果。涉及身份或绑定时保留 `message_id`、角色、`tool_call_id`、`block_key` 与序列信息；涉及内容变化时记录提取和解析是否成功。

`tests/test_browser_sync.py`、`tests/test_worker_browser_message_sync.py` 和 `tests/test_worker_browser_tool_input.py` 提供相关自动化入口。真实网页上的流式、AutoFix 和工具卡交互仍需端到端验证。

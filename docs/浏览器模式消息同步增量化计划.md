# Browser 消息增量同步

> 复核日期：2026-09-26。本文说明 DOM 提取、缓存、服务端同步与客户端渲染的现有链路。

## 提取与缓存

`app/core/driver/browser_js.py` 提供批量探测与定向提取脚本。`IncrementalExtractor` 根据消息顺序、缓存和内容签名选择需要抓取的消息；内容签名包含文本长度、HTML 长度和代码块数量。`BrowserMessageCache` 使用消息 ID 与角色组成缓存键。

定向抓取成功并写入缓存后，提取器更新对应稳定签名。流式尾部使用临时解析路径并保留最终内容的复核机会。提取失败时相应路径可降级到全量抓取。

## 服务端与客户端

`WorkerBrowserMessageSyncBridge` 处理图片、会话状态和工具标识预扫描，再通过 normalizer 生成规范化消息。初次同步或强制刷新发送快照；消息变化发送增量，并附加序列与事件信息。

`app/core/browser_sync/` 维护规范化消息、存储、序列与客户端投影。聊天页面接收同步结果，`MessageArea` 提供增量渲染；`ai_streaming` 分支通过 `_streaming_update()` 更新流式内容。

- `app/ui/pages/chat/page.py`、`app/ui/pages/chat/message_area.py`

## 验收重点

- [ ] 同 ID、不同角色的消息在缓存、规范化、投影与工具绑定中保持正确身份。
- [ ] 流式结束后显示完整正文与代码，定向抓取失败可在后续周期重试。
- [ ] AutoFix 展开代码块后，内容、`block_key` 与工具结果对应。
- [ ] 工具结果及时更新到目标 ToolCallCard，DOM 回流时保持一致。
- [ ] 会话切换、重新连接、虚拟滚动与全量重同步保持顺序。

自动化入口包括 `tests/test_worker_browser_message_sync.py` 和 `tests/test_browser_sync.py`。真实网页验收需记录页面、操作、日志与结果；历史性能数字只用于对应测试场景。

稳定性检查见[Browser 同步与渲染验收](浏览器模式消息同步与增量渲染稳定性优化计划书.md)。

# 消息与回合状态约定

> 复核日期：2026-09-26。Browser 回合、API 流和 UI 展示分别使用明确的状态与事件契约。

## 状态职责

| 层级 | 当前实现 |
| --- | --- |
| Browser 回合 | `app/core/round_state/` 中的 BrowserRoundStateMachine，管理空闲、生成、处理、修复、工具执行与系统发送 |
| Browser 消息 | `app/core/browser_sync/` 中的规范化消息、顺序、快照和增量事件 |
| API 流 | `app/core/api/` 的流状态与 Worker API 流桥接 |
| 上游投影 | `upstream_events.py`、`upstream_consumer.py` 将事件映射为状态和 UI payload |
| 客户端 | 根据会话、消息、流与回合标识更新聊天和工具展示 |

## 维护规则

1. 回合状态转换通过对应状态机或事件入口执行。
2. 流结束、工具结束和回合结束分别处理。
3. 消息身份与顺序使用协议中的标识；网页消息 ID 可能在不同角色间复用，缓存与绑定需包含角色信息。
4. 工具结果关联对应调用，维护 `tool_call_id` 和 `block_key` 的一致性。
5. 内容哈希用于相应内容变化检测；业务状态转换遵循事件与状态契约。
6. 切换会话、取消、恢复和快照重载时，核对事件目标与当前 UI 目标。

## 验收

覆盖重复消息、DOM 折叠/展开、流式中断、取消、工具连续调用和会话切换。检查消息顺序、结果归属及最终状态，并记录真实运行证据。

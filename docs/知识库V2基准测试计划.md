# Knowledge V2 检索质量基准测试计划

## 背景

当前测试只覆盖功能正确性（35 个 pytest case），缺少检索质量的量化评估。
项目落地后 KnowledgeServiceV2 将检索任意代码库，需要一个与业务数据解耦的标准基准来衡量和驱动迭代。

## 目标

建立可复现的检索质量基准，满足：
- 每次改动 chunker/embedder/reranker 后，一条命令看到质量变化
- 指标客观、可对比，不依赖人工判断
- 跑一次 < 30s，适合 CI

## 数据集

### 第一层：CodeSearchNet 多语言子集（标准基准）

来源：GitHub CodeSearchNet Challenge
地址：https://github.com/github/CodeSearchNet

| 语言 | 抽样数 | 说明 |
|------|--------|------|
| Python | 20 | 主力语言，权重最高 |
| JavaScript | 20 | 前端/Node 场景 |
| Java | 15 | 企业级项目常见 |
| Go | 15 | 基础设施/云原生 |
| 合计 | 70 | - |

每条数据包含：
- query: 自然语言描述（英文）
- code: 对应的代码片段
- language: 语言标识
- url: 原始来源（可追溯）

抽样原则：
- 代码长度 5-80 行（过短无意义，过长超出 chunk 边界）
- query 长度 5-20 词（过短歧义大，过长不现实）
- 覆盖不同代码结构：类、函数、配置、算法

### 第二层：非代码文件补充集（手工标注）

| 文件类型 | 数量 | 示例 query |
|----------|------|------------|
| YAML/TOML | 3 | "database connection config" |
| Markdown | 3 | "API authentication docs" |
| Dockerfile | 2 | "multi-stage build setup" |
| Shell | 2 | "deployment script" |
| 合计 | 10 | - |

## 指标

| 指标 | 公式 | 含义 |
|------|------|------|
| MRR (Mean Reciprocal Rank) | avg(1/rank_of_correct) | 正确答案平均排第几 |
| Recall@1 | correct_in_top1 / total | top-1 命中率 |
| Recall@3 | correct_in_top3 / total | top-3 命中率 |
| Recall@5 | correct_in_top5 / total | top-5 命中率 |


```json
{
  "timestamp": "2025-01-15T10:00:00",
  "config": {
```

## 测试流程

```
1. 加载 golden_dataset.json
2. 创建临时 KnowledgeServiceV2 实例
3. 索引所有 code 片段（模拟真实代码库）
4. 逐条执行 query
5. 检查 ground truth code 在结果中的排名
6. 计算 MRR / Recall@K
7. 与 baseline.json 对比，超过阈值则 FAIL
8. 输出分语言的详细报告
```

## 回归守卫

当 baseline.json 存在时，自动对比：
- MRR 下降 > 5% → FAIL
- Recall@3 下降 > 10% → FAIL
- 任意语言 MRR 下降 > 15% → WARNING

## 使用方式

```bash
# 一键跑所有功能测试（不含 benchmark）
pytest

# 跑检索质量基准
pytest -m benchmark -s

# 更新基线（当前指标成为新基线）
pytest -m benchmark -s --update-baseline

# 只跑某种语言的基准
pytest -m benchmark -s -k python

# 全跑（功能 + 基准）
pytest -m "benchmark or not benchmark" -s
```

## 实施步骤

1. 从 CodeSearchNet 下载 Python/JS/Java/Go 数据
2. 按抽样原则筛选 70 条，存入 golden_dataset.json
3. 手工编写 10 条非代码文件 case
4. 实现 test_retrieval_quality.py
5. 首次运行，生成 baseline.json
6. 集成到 CI（可选）

## 迭代示例

```
场景：想测试 reranker 权重调整的效果

1. 跑基准 → MRR=0.72, Recall@3=0.80
2. 修改 reranker 权重 vec:0.6→0.5, keyword:0.25→0.35
3. 再跑基准 → MRR=0.75, Recall@3=0.83
4. 确认提升，更新 baseline
```

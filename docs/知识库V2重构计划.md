# 知识库检索与索引

> 复核日期：2026-09-26。当前实现位于 `app/core/knowledge/`，服务门面位于 `app/core/services/knowledge_service.py`。

## 检索与索引链路

索引流程读取项目文件，经分块、嵌入后写入 Chroma。查询经过候选检索、重排与格式化返回结果。`KnowledgeExecutor` 用单独线程串行处理搜索、索引和预热任务；服务提供缓存、健康状态、错误记录及恢复入口。

| 模块 | 职责 |
| --- | --- |
| `config.py` | 模型、分块和检索配置 |
| `chunker.py` | 代码与文本分块 |
| `embedder.py` | fastembed 嵌入与备用路径 |
| `reranker.py` | TextCrossEncoder 重排及关键词降级 |
| `cache.py` | 查询缓存 |
| `executor.py` | 搜索、索引、预热任务的串行队列 |
| `service.py` | 索引、检索、路径清理、健康状态与恢复 |
| `reindex_runner.py` | 项目重建索引任务 |

## 项目隔离与同步

知识库路径由 `ProjectContext` 按项目标识组织在 `{APP_ROOT}/knowledge_bases/`。项目切换需要同步服务路径、连接和缓存。

服务支持 `list_indexed_paths()` 和 `delete_paths()`，索引维护可以处理已删除文件。项目扫描需应用忽略规则，避免将构建产物、虚拟环境或其它项目缓存加入索引。

## 运行与排查

1. 查看 `get_health()` 或 `get_stats()` 的状态、实际检索路径、嵌入与重排模式。
2. 按日志阶段确认问题发生在导入、初始化、检索还是重排。
3. 使用预热、索引和查询入口复现，保留耗时、模型模式与异常证据。
4. 主模型不可用时确认降级结果；需要恢复时检查 `try_recover_main_path()`。

运行 fastembed、ONNX、TextCrossEncoder 和 Chroma 组合时，需要在目标环境验证模型加载、搜索与稳定性。

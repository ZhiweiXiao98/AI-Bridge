# 日志与调试使用说明

> 复核日期：2026-09-26。应用通过标准 logging、追踪上下文、probe 与 Qt 日志面板组织调试信息。

## 记录日志

业务模块使用 `app.core.logging.get_logger()`，指定模块名和 `side`。`init_logging()` 配置控制台和轮换文件，默认目录为 `{APP_ROOT}/logs/`；日志级别、输出目录及控制台开关由初始化参数控制。

文件和面板 handler 对应用命名空间进行过滤。面板通过 Qt Signal 接收结构化字段，支持按级别、来源等条件筛选；噪声控制用于高频事件。

## 追踪与探针

`TraceContext` 保存 `trace_id`、`conversation_id`、`round_id`、`stream_id` 等字段，使用线程局部存储管理活跃上下文。跨线程和远程边界需要明确传递标识，并验证接收端日志是否携带正确值。

`app.core.debug.probe` 提供统一探针和标签、来源、级别、详细模式配置。新增调试点使用 logging 或 probe，说明发生了什么、关联哪个请求以及处理结果。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `app/core/logging/log_manager.py` | 日志初始化、handler、级别与目录 |
| `app/core/logging/trace_context.py` | 追踪上下文与标识 |
| `app/core/logging/noise_control.py` | 噪声配置 |
| `app/core/debug/probe.py` | 调试探针与过滤 |
| `app/ui/logging/qt_log_handler.py` | 日志到 Qt 面板的桥接 |

## 排查顺序

1. 确认发生问题的客户端、服务端、会话和操作时间。
2. 检查日志级别、来源与面板过滤条件。
3. 按请求、回合或流标识连接调用链上的日志。
4. 对照请求快照、工具反馈和 UI 状态，定位最早出现差异的边界。
5. 增加必要探针，复现后保存证据并控制高频输出。

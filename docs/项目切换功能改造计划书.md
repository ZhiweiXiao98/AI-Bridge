# 项目切换与数据路径

> 复核日期：2026-09-26。本文描述项目切换入口、资源路径与验收边界。

## 使用入口

顶部项目菜单和 Browser / API 聊天栏的项目按钮支持打开目录、选择最近项目和返回软件目录。UI 切换本地 `ProjectContext` 后，通过 `worker.switch_project(path)` 通知服务端。

## 路径与数据

| 数据 | 当前位置与规则 |
| --- | --- |
| 软件资源 | `APP_ROOT` |
| 当前工作项目 | `ProjectContext.get_project_root()` |
| 知识索引 | `{APP_ROOT}/knowledge_bases/{project_hash}/`，项目标识来自规范化路径 |
| 最近项目 | `{APP_ROOT}/projects.json`，记录最近目录和上次项目 |
| API Source 对话 | 显式使用 `{APP_ROOT}/config/conversations/`；对话记录保存 `project_root` / `project_name` |
| 未指定目录的 ConversationStore | 使用 `{project_root}/conversations/`，收到项目切换通知后保存当前会话并重载目标目录 |

`ConversationStore` 显式指定目录时，项目切换保持该目录及索引。当前 API 对话列表按项目元数据分组；跨项目的聚合加载、点击路由和操作隔离仍需完善。

## 切换流程

`ProjectContext.switch_to()` 校验目标目录，发出 `about_to_switch`，更新项目路径并调用 `os.chdir()`，随后发出 `project_switched`，最后保存最近项目列表。

`WorkerProjectSwitchBridge` 接收切换信号，处理已持有的测试子进程与 Docker 容器，更新 Docker 项目路径，并安排 API 对话列表刷新。各服务按自身信号连接更新文件、Git 或知识库资源。

当前路径切换包含进程级 cwd 变化。消除隐式 cwd 依赖、校验进行中任务的取消覆盖范围，是后续切换稳定性工作。

## 代码位置

- `app/core/project_context.py`：路径、信号与最近项目持久化。
- `app/core/worker_modules/worker_project_switch.py`：Worker 资源切换。
- `app/core/conversation_store.py`、`app/core/api_source.py`：对话目录与项目元数据。
- `app/ui/components/panels/project_menu.py`、`app/ui/pages/chat/status_bar.py`：用户入口。
- `app/ui/pages/chat/api_session_list.py`：按项目分组展示会话。

## 维护约定

软件配置与资源使用 `APP_ROOT`，项目业务路径使用 `ProjectContext`。修改共享路径时，应同时检查本地 Worker 与远程 RPC 的目标项目。对话目录规则以调用方传入的 `storage_dir` 为准。

## 验收清单

- [ ] 在两个不同项目间切换，核对 UI、服务端、文件操作、Git、Docker 和知识库的目标路径。
- [ ] 进行中工具、测试或索引任务在切换时正确结束或报告状态。
- [ ] API 对话项目分组、历史重载和跨项目点击路由一致。
- [ ] 重启后恢复上次项目和最近列表；不存在目录有明确处理。
- [ ] 返回软件目录、重复选择当前目录、带中文或空格路径均可用。
- [ ] 将剩余 `os.getcwd()` 使用逐项改为明确的软件或项目路径。

完整端到端切换验收尚需记录；能力与优先级见[当前项目状态](当前项目状态.md)。
